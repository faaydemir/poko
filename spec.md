# Port — macOS local development port manager

Build a working, simple, polished macOS-only product in this empty repository. Two separate apps: Port Server (background backend) and Port (native menu bar UI). Implement, build, test, and package both. User wants it installed and MCP added to existing agents. Do not stop at planning.

## Behavior
- Central durable registry allocates free loopback TCP ports for a named app, with absolute project folder, group, optional icon metadata. Normalize payment_api to payment-api. Validate DNS labels.
- Agent requests a port, receives reservation ID, port, suggested hostname, URL, environment instructions; then accepts/activates it, creating the reverse proxy route. Idempotent requests for same app/project. Related apps (payment-api/payment-ui) use adjacent ports within persistent group blocks (e.g. 4100-4119, next group 4120-4139), skipping occupied and reserved ports. Concurrent requests cannot allocate duplicate ports. Allocations persist across restarts. Explicit release never kills processes.
- Expose real standards-compliant MCP stdio bridge using official SDK, talking to shared daemon. Tools request_port, accept_port, list_apps, inspect_ports, release_port. Clear input schemas, actionable failures. Multiple agents share daemon registry.
- Automatic localhost HTTP reverse proxy routing by hostname; http://payment-api.localhost -> allocated port. Use Node native proxy or maintained proxy library with HTTP streaming and WebSocket support. Bind only loopback. Try port 80; gracefully report occupied/permission failure, expose configurable fallback URL with actual port. No false claim of portless URLs if 80 unavailable. No root whole-backend execution. No /etc/hosts edits needed for .localhost; document browser limitations. Handle IPv4/IPv6 upstream listeners. Never forward arbitrary unregistered hosts, or targets beyond loopback. Local authenticated control API separate from proxy, token stored mode 0600; reject browser origins and unexpected Hosts for control API. UI and bridge read token from user application support dir. Daemon ownership/single instance handled cleanly.
- macOS process discovery via lsof: port, process name, PID, project cwd when available. Clearly show unknown paths when permission unavailable. Discover existing listeners without modifying processes. Exclude own proxy/control services. Optional import existing port into registry with validation, not reallocation. Detect running/stopped/conflict, distinguish reservation from active route.
- UI is native SwiftUI/AppKit macOS MenuBarExtra (macOS 13+): clean compact menu bar panel with app mark, running count, server/proxy status, search, grouped app rows, status dots, clickable hostname and port, copy URL, reveal folder, release action confirmation, refresh and start/retry backend, quit UI separately. Show discovered services separately with import action. Add/reserve app form with name/group/folder. Use workspace folder icon or SF symbol fallback. Clear empty/loading/error states. No web UI needed. Responsive async networking, periodic refresh, no blocked main thread. Include a normal management window if it makes menu panel simpler.
- Package dist/Port.app and dist/Port Server.app (launcher for backend, optional minimal status) with proper Info.plists/icons. Backend can be Node.js with pinned npm deps and native launcher; use installed absolute node path safely. Swift Package build native UI. Provide scripts build/install/uninstall, per-user launch agent for backend with logs and cleanup, reproducible README. No sudo install requirement. Install to ~/Applications and load user daemon if possible. Do not overwrite existing unrelated agent config.
- Agent integration installer supports Codex (codex mcp add), Claude Code (claude mcp add user scope), Cursor ~/.cursor/mcp.json with backups and merge preservation. Use stdio bridge absolute path, actual node executable. Provide --dry-run and targeted options. Write AGENTS.md usage instructions for this project; provide opt-in global guidance snippet.

## Scope and validation
Keep code small and readable. Node LTS available, Swift 6 available on Apple Silicon macOS. No cloud accounts, no AI API calls, no telemetry, no Docker. Use official MCP SDK docs and current platform docs when needed. Test real concurrent allocations, persistence, collision skip, idempotency, release, hostile input, route unknown host/offline, HTTP and WebSocket forwarding, MCP initialize/tools list/tool execution end to end against test daemon isolated data and unprivileged ports. Build Swift UI and app bundles. Smoke-test launch/start/stop. Avoid polluting live registry with fixtures. Do not kill unrelated apps or commandeer occupied ports. Document unavoidable limitation: allocation is advisory until target process binds; verify collision at acceptance and show conflicts rather than promise OS reservation across external process startup. If chosen port becomes occupied before accept, require matching project/process identity or explicit import confirmation rather than silently proxy to unknown service.
